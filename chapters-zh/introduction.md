# 引言

本书探讨一个核心问题：**顶级生产级 Agent 如何通过使用变得更好？**

不是理论上的。不是 arxiv 论文里的。而是在数百万用户使用的已发布产品中。

本书涵盖的 Agent 不是研究原型。它们是：

- **Claude Code** — Anthropic 的编程 Agent（截至 2026 年 3 月，年化收入 25 亿美元）
- **Cursor** — AI 优先的 IDE（每日 4 亿+ AI 请求，10 亿美元 ARR）
- **OpenAI Codex** — 具备记忆、子 Agent 和插件的编程 Agent
- **Hermes Agent** — Nous Research 的自我改进 Agent（99K+ GitHub stars）
- **OpenClaw** — 开源个人 AI Agent（350K+ GitHub stars）
- **GitHub Copilot** — 微软的编程助手，具备 Agent 式记忆
- **Gemini CLI** — Google 的终端 Agent，配备记忆管理器
- **Windsurf** — Codeium 的 Cascade Agent，支持自动生成记忆
- **Devin** — Cognition 的自主软件工程师，具备自我验证能力
- **Manus** — 9 个月内达到 1 亿美元 ARR 的自主 Agent

这些产品中的每一个都构建了自我进化机制。它们的方法各不相同——有些使用文件系统持久化，有些使用记忆数据库，有些使用学习规则，有些使用技能库。但它们都在解决同一个问题：一个不会学习的 Agent 就是一个永远重复相同错误的 Agent。

本书提炼了它们做了什么、如何做到的，以及你可以为自己的 Agent 借鉴什么。

## 证据标准

本书中的每一个论断都可追溯到以下四类来源之一：

1. **泄露的源代码** — Claude Code npm source map（2026 年 3 月）为我们提供了 512K 行代码，包括 `SystemPromptBuilder`、记忆发现逻辑、压缩系统和反蒸馏对抗措施。

2. **开源代码仓库** — Hermes（`NousResearch/hermes-agent`，MIT 许可证）和 OpenClaw 是完全可读的。我们引用了文件路径、函数名和行号范围。

3. **官方文档和博客文章** — Cursor 的工程博客、Peak Ji 的"Context Engineering for AI Agents"演讲、OpenAI 的 Codex API 文档、Devin 的产品更新、Windsurf 的架构文章。

4. **已发布产品的行为** — 生产系统中可观察、可复现的行为。当我们无法阅读源代码时，我们会明确说明，并描述我们观察到的内容。

我们**不**引用的内容：尚未发布产品的学术论文。从第一性原理提出的分类体系。关于 Agent *可能*做什么的猜测。会议海报。综述论文。

我们对访问级别保持透明，因为它决定了置信水平：

| 系统 | 主要来源 | 置信度 |
|--------|---------------|-----------|

| Cursor | 工程博客 + 开源 Priompt | 架构级 |

| Copilot | 产品文档 + 可观察行为 | 外部观察 |
| Gemini CLI | 官方文档 + CLI 源代码 | 文档 + CLI 源代码 |

## 本书不是什么

- **不是学术论文综述。** 只有在论文直接影响了已发布产品时才会被引用。
- **不是从零构建 Agent 的教程。** 你应该已经知道什么是 Agent 循环。
- **不是框架对比图表。** 我们深入探讨机制，而非功能列表。

---

## 如何阅读

每一章深入介绍一个生产系统。阅读你关心的系统。第 11 章将所有系统的模式综合为一本你可以应用的实战手册。

**第一部分**（第 1-4 章）：全景概述以及三个最深入的系统——Claude Code、Cursor、Hermes。从这里开始。

**第二部分**（第 5-7 章）：技能生态系统——OpenClaw、ClawHub、SkillHub，以及使技能发挥作用的设计模式。

**第三部分**（第 8-10 章）：三种不同的理念——Manus（上下文工程）、Codex（压缩）、Devin（自我验证）。

**第四部分**（第 11-12 章）：综合所有十个系统的生产实战手册，以及开放问题。

每一章都是独立的。但第 1 章提供了后续章节依赖的比较框架。

## 排版约定

- **代码块**包含从生产系统中提取的实际源代码或配置。除非明确标注，否则不是伪代码。
- `等宽字体`标记文件路径、函数名、配置键和 CLI 命令。
- **粗体**标记首次引入的关键概念。
- *斜体*标记直接引用自源代码注释或文档的内容。
- 当我们引用源代码时，会注明原始仓库中的文件路径。
